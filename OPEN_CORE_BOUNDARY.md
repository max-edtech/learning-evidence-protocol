# Open-core boundary

This repository is deliberately useful and deliberately incomplete.

## Open in this repository

- protocol vocabulary;
- JSON Schemas;
- synthetic examples;
- conformance validation;
- static reference viewer;
- compatibility notes and mappings.

These components should remain portable enough for teachers, researchers,
open-source lessons, and commercial products to exchange evidence records.

## Outside this repository

- identifiable learner data;
- proprietary datasets and golden cases;
- learner profiles;
- diagnostic or recommendation models;
- scoring weights and commercial rubrics;
- production dashboards;
- organization-specific integrations;
- hosting, security, support, and compliance services.

Those components may be open or proprietary in separate projects. LEP does not
require either model.

## Why MPL-2.0

MPL-2.0 applies copyleft at the file level. If someone distributes a modified
version of an MPL-covered file, the covered source remains available under the
MPL. Separate files can still be combined with the protocol in a larger
proprietary work.

This creates a practical boundary:

- improvements to the shared protocol can flow back to the commons;
- adopters do not have to disclose an entire application;
- commercial value can live in data, operations, integrations, and domain
  intelligence rather than artificial scarcity around the interchange format.

This document is a project policy, not legal advice.
